# 方法說明與模型卡

所有方法在 `src/analytics/`，測試在 `tests/test_analytics.py`（手算小例子與合成資料驗證）與 `tests/test_export_web.py`（整條管線）。

## 正式資料與合成測試資料

正式 Pages 與 Docker 建置使用 FinMind 公開歷史日行情，並以 provenance 記錄來源及非合成狀態；資料在建置時取得，網站執行時不即時連線。以下固定種子行情與其已知市場狀態是方法驗證用的合成 fixture，不是正式網站資料或真實股票績效描述。合成資料只用於本機／CI 方法測試與 PR 預覽。

## 市場狀態（`hmm.py`）

- 縮放的前向後向演算法，Baum-Welch 估計；EM 每次疊代對數概似不遞減（有測試）。
- 初始化：依 20 日滾動變異數的分位數分組，再加隨機擾動；4 組初始化取最佳。
- 狀態依波動排序，所以「狀態 0」永遠是最平穩的。
- 跳空日（60 日穩健 z > 5）在估計時視為缺值：缺值日對所有狀態的發生機率相同，只影響狀態路徑，不影響參數。
- BIC 比較 1–3 個狀態；網站展示 3 狀態模型並揭露 BIC 的選擇。股票上 BIC 偏好 2 個狀態（平穩與震盪波動相近），對照組選 1 個。
- 準確率：Viterbi 路徑在所有標籤排列中取最佳對齊後與真實狀態比對。

## 異常事件研究（`events.py`）

- 校準：前252個交易日不評分；每63日僅以此前最多504日重估HMM，接下來區段不參與擬合。全歷史市場狀態圖為回顧性展示，不用作異常偵測的參數。
- z 分數：以 HMM 的一步預測（第 t−1 天的過濾機率乘轉移矩陣）得到的混合分布平均與標準差計算，|z| > 5 為異常。
- 異常報酬：事件窗 [−5, +10]，減去事件前第 120 至第 11 天的平均報酬（平均調整模型）。
- 事件後 CAR 從 +1 日開始累積，95% 區間為重抽事件 2,000 次的百分位數（固定種子）。
- 結果：以當次匯出的 events.json 與 provenance.json 為準，綁定資料範圍及輸入SHA-256；合成fixture的注入效果只用於方法測試，不沿用未版本化的固定成績。

## 誠實回測（`backtest.py`）

- 策略：短均線 5–50、長均線 20–250 的交叉（48 組），只做多或空手；部位以當日收盤決定、賺取次日報酬；每次換倉成本 0.1%。
- 前視偏誤檢查：把價格截短 8 次重跑，任何歷史部位改變即失敗；測試中一個偷看明天價格的策略會被抓到。
- 樣本內／外：前 60% 與後 40%；walk-forward：2 年訓練、半年測試、測試窗不重疊。至少需要631筆共同價格才能形成一個完整樣本外區段；資料不足明確拒絕匯出。樣本外帳戶由現金起始，跨區段依實際部位收取換倉成本，不沿用各獨立策略假想前一部位的成本。
- CSCV：資料切 10 塊，所有 C(10,5)=252 種組合中，樣本內冠軍在樣本外的相對排名取 logit，logit ≤ 0 的比例即 PBO。
- Deflated Sharpe Ratio：以試驗次數與 Sharpe 的變異估計「純運氣下的最大 Sharpe」，並修正偏態與峰態。

## 壓力測試（`risk.py`、`web/src/lib/stress.ts`）

- 區塊 bootstrap：每條路徑反覆抽一個起點、取連續 L 天的日報酬，直到填滿期間。
- Python 與 TypeScript 都用 mulberry32（逐位相同的移植），抽樣順序一致，匯出的參考案例讓 Vitest 檢查兩邊誤差 < 1e-9。
- VaR 為期末損失的分位數（線性插值，與 numpy 相同），CVaR 為大於等於 VaR 的平均損失。

## 不應該怎麼用

- 不是投資建議或交易訊號。
- 合成資料上的表現是方法的上限，不代表任何真實股票。
- 過度擬合檢定只能告訴你「這套搜尋不可信」，不能保證「通過的參數會賺錢」。
